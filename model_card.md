# Model Card — AutoML-классификатор опухолей молочной железы

## 1. Общая информация (Model Details)

| Поле | Описание |
|---|---|
| Проект | [automl-project](https://github.com/framey1/automl-project) |
| Тип модели | Бинарный классификатор на основе автоматически выбираемого алгоритма scikit-learn |
| Назначение | Классификация диагностических наблюдений по числовым характеристикам клеточных ядер |
| Статус | Учебный / демонстрационный ML-пайплайн; клиническая валидация не проводилась |
| Разработчик | Автор проекта, указанный в README репозитория |
| Версия модели | Не зафиксирована отдельным идентификатором версии; артефакт формируется при запуске обучения |
| Реализация | [`src/automl.py`](https://github.com/framey1/automl-project/blob/main/src/automl.py), [`src/train.py`](https://github.com/framey1/automl-project/blob/main/src/train.py) |
| Сохранённая модель | `models/best_model.joblib` (создаётся после обучения) |

**Важно:** AutoML здесь не означает одну неизменную архитектуру. Код перебирает четыре семейства алгоритмов и выбирает лучший обученный конвейер на основе оценки на кросс-валидации. Название фактически выбранного алгоритма и его параметры следует брать из результатов конкретного запуска, а не предполагать заранее.

## 2. Предполагаемое использование (Intended Uses)

**Основной сценарий:** демонстрация автоматизации подготовки данных, подбора классификатора, оценки качества, сохранения модели и получения прогноза для числовых диагностических наблюдений.

Модель решает задачу **бинарной классификации**: по 30 признакам наблюдения предсказывает один из двух классов.

- `0` — злокачественная опухоль (*malignant*).
- `1` — доброкачественная опухоль (*benign*).

Эта кодировка соответствует `sklearn.datasets.load_breast_cancer`.

**Допустимое использование:** учебные эксперименты, проверка ML-пайплайна, сравнение алгоритмов и исследовательские демонстрации на данных аналогичного формата.

**Недопустимое использование:** самостоятельная постановка диагноза, исключение рака, назначение лечения, автоматическая маршрутизация реальных пациентов без клинической проверки и участия квалифицированного специалиста. Прототип не является медицинским изделием, прошедшим клиническую оценку.

## 3. Данные (Data)

Источник — встроенный в scikit-learn набор **Breast Cancer Wisconsin (Diagnostic)** (`load_breast_cancer`).

| Характеристика | Значение |
|---|---|
| Количество наблюдений | 569 |
| Количество входных признаков | 30 |
| Признаки | Числовые характеристики клеточных ядер, включая радиус, текстуру, периметр, площадь, гладкость, компактность и др.; используются признаки mean, error и worst |
| Целевая переменная | `target` (0 — malignant; 1 — benign) |
| Источник в коде | `src/etl.py` |
| Исходный CSV | `data/raw/breast_cancer.csv` (генерируется ETL) |
| Разбиение | 80% train / 20% test (`TEST_SIZE = 0.2`) |
| Воспроизводимость | `RANDOM_STATE = 42`; разбиение стратифицировано по классу |

Этап преобразования проверяет непустоту таблицы, наличие `target`, удаляет строки с пропусками при их наличии и разделяет данные на обучающую и тестовую части. Масштабирование `StandardScaler` включено в конвейеры Logistic Regression и SVC; для двух ансамблевых моделей отдельный scaler не используется.

**Ограничение данных:** 569 наблюдений из одного учебного набора не гарантируют обобщение на пациентов, лаборатории и оборудование вне исходной выборки. В проекте не показана внешняя клиническая валидация.

## 4. Метод обучения (Training Procedure)

Функция `train_automl(X_train, y_train, scoring="f1", cv=3)` формирует кандидатов и выполняет `GridSearchCV` для каждого из них.

| Кандидат | Предобработка | Настраиваемые параметры в репозитории |
|---|---|---|
| Logistic Regression | `StandardScaler` | `C`: 0.1, 1.0; `solver`: liblinear |
| Random Forest | Без отдельного scaler | `n_estimators`: 50; `max_depth`: None, 5 |
| SVC | `StandardScaler` | `C`: 1.0; `kernel`: rbf, linear; `probability=True` |
| Gradient Boosting | Без отдельного scaler | `n_estimators`: 50; `learning_rate`: 0.1; `max_depth`: 2 |

- Для каждого семейства модели используется трёхблочная кросс-валидация (`cv=3`) на тренировочной части.
- Главный критерий подбора и выбора победителя — `F1` **для положительного класса `1` (доброкачественная опухоль)** при стандартных настройках `scikit-learn`.
- Побеждает кандидат с максимальным средним `best_cv_score`; затем уже дообученная лучшая конфигурация оценивается на отложенной тестовой части.
- Конкретный победитель зависит от выполнения обучения и должен фиксироваться по полю `model_name` в `reports/monitoring_record.json`.

Код: [`src/automl.py`](https://github.com/framey1/automl-project/blob/main/src/automl.py), [`src/config.py`](https://github.com/framey1/automl-project/blob/main/src/config.py).

## 5. Входы и выходы (Inputs and Outputs)

**Вход для прогнозирования:** CSV-файл с наблюдениями, где каждая строка содержит те же 30 числовых признаков, что использовались при обучении. Требуются согласованные имена и порядок признаков; столбец `target` для прогнозирования не нужен.

**Выход:** CSV с исходными признаками и двумя дополнительными столбцами:

| Поле | Значение |
|---|---|
| `prediction` | Предсказанный класс: 0 — злокачественная, 1 — доброкачественная |
| `probability_class_1` | Оценка моделью вероятности класса 1 (доброкачественная опухоль), от 0 до 1 |

Значение `probability_class_1` **не является вероятностью злокачественности**. Для клинической интерпретации требовалась бы отдельная проверка калибровки и пригодности модели.

Команда после успешного обучения:

```bash
python -m src.predict путь/к/наблюдениям.csv --output predictions.csv
```

Реализация: [`src/predict.py`](https://github.com/framey1/automl-project/blob/main/src/predict.py).

## 6. Метрики и оценка (Performance)

В `src/evaluate.py` на тестовой выборке рассчитываются:

| Метрика | Что измеряет |
|---|---|
| Accuracy | Доля всех правильных классификаций |
| Precision (`pos_label=1`) | Доля правильно предсказанных доброкачественных среди всех предсказанных доброкачественных |
| Recall (`pos_label=1`) | Доля обнаруженных доброкачественных среди всех действительно доброкачественных |
| F1-score (`pos_label=1`) | Гармоническое среднее Precision и Recall для доброкачественного класса |
| ROC-AUC | Способность оценок `predict_proba(X)[:,1]` разделять классы по разным порогам |

**Фактические значения:** не подтверждены опубликованным файлом метрик в репозитории при подготовке карточки. После запуска `python -m src.train` они записываются в `reports/metrics.json`; выбранный алгоритм и `best_cv_f1` — в `reports/monitoring_record.json`. Не следует указывать гипотетические проценты качества как результаты измерения.

**Важное замечание о безопасности:** выбор алгоритма по `F1` для класса `1` (доброкачественная опухоль) **не эквивалентен оптимизации выявления злокачественных опухолей**. Для возможного медицинского исследования необходимо отдельно оценивать чувствительность по классу `0` (злокачественная опухоль), долю пропусков злокачественных случаев, специфичность, матрицу ошибок, калибровку и доверительные интервалы. Клинические пороги приемлемости в проекте не установлены.

## 7. Ограничения, риски и этические аспекты (Limitations / Ethical Considerations)

1. **Риск ложноотрицательной оценки злокачественности:** фактически злокачественное наблюдение может быть классифицировано как доброкачественное. Это особенно опасный тип ошибки при медицинском применении.
2. **Ограниченная репрезентативность:** один небольшой публичный датасет; неизвестна переносимость на иные популяции, лабораторные условия и оборудование.
3. **Нет внешней валидации:** тестирование на случайной части того же датасета не доказывает пригодность для реальной медицинской практики.
4. **Нет анализа по подгруппам:** в проекте не представлена проверка качества по возрастным, демографическим или другим клинически значимым подгруппам.
5. **Нет подтверждённой калибровки вероятностей:** `predict_proba` нельзя автоматически трактовать как достоверно откалиброванный индивидуальный риск.
6. **Требования к схеме входа:** CSV должен соответствовать структуре и семантике обучающих признаков; в `src/predict.py` нет отдельной полноценной проверки допустимых диапазонов и происхождения значений.
7. **Ограничение мониторинга:** в коде есть запись метрик обучения в JSON и попытка логирования в MLflow, но нет подтверждённого мониторинга дрейфа данных, качества реальных прогнозов или автоматически настроенного переобучения по ухудшению качества.

## 8. Воспроизводимость и жизненный цикл (Maintenance)

Запуск из корня репозитория:

```bash
pip install -r requirements.txt
python -m src.train
pytest -q
```

После обучения формируются `models/best_model.joblib`, файлы метрик, графики (распределение классов, матрица ошибок, ROC-кривая и при доступности важность признаков) и запись мониторинга. Автоматизация тестов/запуска описана в `.github/workflows/ci.yml`; имеется Dockerfile.

При каждом новом обучении следует сохранять название выбранной модели, её гиперпараметры, значения метрик, версии библиотек и дату запуска. При возможном переходе к реальному использованию требуются независимая проверка, управление версиями, контроль качества входных данных, клиническая оценка и надзор специалиста.
