## 1. Бизнес-задача

Цель проекта — автоматизировать полный ML-пайплайн для бинарной классификации медицинских наблюдений: предсказать, является ли опухоль доброкачественной или злокачественной на основе числовых признаков клеточных ядер.

Практическая ценность: такой пайплайн может использоваться как демонстрационная система поддержки принятия решений. Модель не заменяет врача, но показывает, как автоматизировать подготовку данных, обучение, подбор модели, оценку качества, контейнеризацию, CI/CD и мониторинг.

## 2. Данные

Используется датасет **Breast Cancer Wisconsin Diagnostic**, встроенный в `scikit-learn`.

Состав данных:

- 569 объектов;
- 30 числовых признаков;
- целевая переменная `target`;
- тип задачи: бинарная классификация.

Данные автоматически сохраняются в `data/raw/breast_cancer.csv` при запуске ETL.

## 3. Схема ML-пайплайна

```text
Extract: загрузка датасета из sklearn
        ↓
Transform: проверка данных, удаление пропусков, train/test split
        ↓
AutoML: автоматический перебор моделей и гиперпараметров
        ↓
Evaluate: Accuracy, Precision, Recall, F1, ROC-AUC
        ↓
Load: сохранение модели, метрик и графиков
        ↓
Monitoring: логирование метрик в MLflow и JSON
        ↓
CI/CD: тесты и запуск пайплайна в GitHub Actions
```

## 4. ETL

### Extract

Функция `extract()` загружает датасет Breast Cancer Wisconsin Diagnostic через `sklearn.datasets.load_breast_cancer` и сохраняет его в CSV.

### Transform

Функция `transform()` выполняет:

- проверку, что датасет не пустой;
- проверку наличия целевой колонки;
- удаление пропусков при их наличии;
- разделение на train/test с сохранением пропорции классов.

### Load

Функция `load_processed()` сохраняет обработанные выборки:

- `X_train.csv`;
- `X_test.csv`;
- `y_train.csv`;
- `y_test.csv`.

## 5. AutoML / кастомная автоматизация обучения

В проекте реализован кастомный AutoML-блок на основе `scikit-learn`:

- автоматически создаются пайплайны для нескольких алгоритмов;
- для каждого алгоритма выполняется `GridSearchCV`;
- модели сравниваются по F1-score;
- лучшая модель выбирается автоматически.

Проверяются модели:

- Logistic Regression;
- Random Forest;
- SVC;
- Gradient Boosting.

Файл реализации: `src/automl.py`.

## 6. Метрики модели

После запуска `python -m src.train` метрики сохраняются в `reports/metrics.json`.

Используемые метрики:

- Accuracy;
- Precision;
- Recall;
- F1-score;
- ROC-AUC.

## 7. Визуализации

Графики сохраняются в `reports/figures/`:

- `class_distribution.png` — распределение классов;
- `confusion_matrix.png` — матрица ошибок;
- `roc_curve.png` — ROC-кривая;
- `feature_importance.png` — важность признаков, если выбранная модель поддерживает такую интерпретацию.

## 8. Тестирование

Тесты находятся в папке `tests/`.

Запуск:

```bash
pytest -q
```

Проверяется:

- что датасет загружается;
- что целевая колонка существует;
- что train/test split создаётся корректно;
- что AutoML-модель может обучиться и сделать предсказания.

## 9. Docker

Контейнеризация нужна для воспроизводимого запуска пайплайна в одинаковом окружении.

Сборка образа:

```bash
docker build -t automl-project .
```

Запуск контейнера:

```bash
docker run --rm automl-project 
```

Функции контейнеризации:

- изоляция зависимостей;
- воспроизводимость окружения;
- переносимость проекта между компьютерами;
- единая команда запуска обучения.

## 10. CI/CD

CI/CD реализован через GitHub Actions в файле `.github/workflows/ci.yml`.

При каждом `push` или `pull_request` выполняется:

1. загрузка репозитория;
2. установка Python 3.13;
3. установка зависимостей;
4. запуск тестов;
5. запуск ML-пайплайна.

Команды Git, использованные для работы:

```bash
git init
git add .
git commit -m ""
git push
```

## 11. Мониторинг

Мониторинг реализован двумя способами:

1. Локальный JSON-файл `reports/monitoring_record.json` с параметрами и метриками запуска.
2. MLflow-логирование метрик, параметров и модели.

Запуск MLflow UI:

```bash
mlflow ui
```
